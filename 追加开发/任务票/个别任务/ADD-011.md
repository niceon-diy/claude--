### ADD-011｜设计、生成并执行单体测试，修复失败

优先级：最高优先：追加开发  
业务状态：未开始（尚未在公司工程执行）  
GitHub：https://github.com/niceon-diy/claude--/issues/12

### 目的

用独立的预期结果和实际执行证据，确认追加改修的各单元按设计运行。

### 前置任务

- [ADD-010｜实现追加改修 Source，执行构建和静态检查](https://github.com/niceon-diy/claude--/issues/11)

按每个实际目标项目判断必要成果是否齐全，或是否有不适用依据；不是要求等待前置任务的全部项目一起完成。

### 输入

- 要求、详细设计、被测 Source 版本
- 单体测试标准、既有框架、环境／数据／Mock／Stub 步骤

### 实际执行步骤

1. 确认公司定义的单体边界。设计确定后的用例准备可与 ADD-010 并行，但执行结果必须对应实际改修版。
2. 把正常、异常、边界、空值、重复等必要观点关联到设计要求，确定输入与预期值，不能只从实现反推正确答案。
3. 准备测试数据、夹具、Mock／Stub 和断言，明确替代哪些外部依赖以及前后状态。
4. 记录并执行实际命令、参数、工作目录、版本、环境，保存逐用例的成功／失败／中断、日志及必要覆盖信息。
5. 将失败区分为 Source、用例、设计、环境问题，修改并复测；不能通过把预期值改成符合错误 Source 来消除失败。

### 成果物

- 设计要求→测试观点→用例→输入→预期依据→断言追踪表
- 执行报告、失败／修复／复测记录、实际测试的 Source 版本

### 完成条件

- [ ] 用例编制、实际执行和通过分别记录状态
- [ ] 必要用例有执行证据，未执行项保留为剩余工作
- [ ] 公司单体结束条件及交给连接测试的版本明确

### 缺失或失败时

保存缺失项、实际已检查范围、受影响结论／对象、确认人或资料及最短补充方式，并继续可独立完成的工作。重要规格矛盾不能擅自消解；没有执行、没有生成或没有测试的内容不得报告完成。

## 日本語（単独でコピーして実行可能）

### ADD-011｜単体テストを設計・生成・実行し失敗を修正する

優先区分：最優先：追加開発  
業務状態：未着手（会社工程で実行前）  
GitHub：https://github.com/niceon-diy/claude--/issues/12

### 目的

追加改修の各単位が設計どおり動くことを、独立した期待結果と実行証拠で確認する。

### 前提チケット

- [ADD-010｜追加改修のSourceを実装しビルド・静的確認を行う](https://github.com/niceon-diy/claude--/issues/11)

各実案件について必要な成果が揃うか、不適用の根拠があるかを判定する。前提チケットの全案件が一斉に完了するまで待つ意味ではない。

### 入力

- 要求・詳細設計・被試験Source版
- 単体テスト標準、既存フレームワーク、環境・データ・Mock／Stub手順

### 実際に行う手順

1. 会社で単体とする境界を確認する。設計確定後の用例準備はADD-010と並行可能だが、実行結果は実際の改修版に対応させる。
2. 正常・異常・境界・空値・重複など対象に必要な観点を設計要求へ対応させ、入力と期待値を決める。実装からの逆算だけで正解を作らない。
3. テストデータ、フィクスチャ、Mock／Stubとアサーションを用意し、外部依存の代替範囲と前後の状態を明確にする。
4. 実際の命令・引数・作業ディレクトリ・版・環境を記録して実行し、用例別の成功／失敗／中断、ログと必要なカバー情報を保存する。
5. 失敗をSource・用例・設計・環境に切り分けて修正と再試験を行う。誤ったSourceに合わせた期待値変更で失敗を消さない。

### 成果物

- 設計要求→試験観点→用例→入力→期待根拠→アサーションの追跡表
- 実行報告、失敗・修正・再試験の記録、試験したSource版

### 完了条件

- [ ] 用例作成・実行・通過が別状態で記録されている
- [ ] 対象範囲の必要用例に実行証拠がある、未実行は残件として扱われる
- [ ] 会社の単体終了条件と接続試験へ渡す版が明確

### 不足・失敗時

不足項、実際に調べた範囲、影響する結論／対象、確認先・資料と最短の補充方法を保存し、独立して進められる作業は続ける。重要な仕様矛盾を勝手に解消せず、未実行・未生成・未試験の内容を完了と報告しない。

### 会社Claudeへの共通実行条件

この作業は、会社内で実際にアクセスできる業務工程に対して実行する。本リポジトリは依頼とテンプレートを提供するもので、会社の調査・実装・試験が完了した証拠ではない。

- まず実工程で有効なルール、現在タスク、既存成果を読む。すでに調べられる情報をユーザーへ再入力させない。歴史資料にある権限や特定環境を現在の承認とみなさない。
- 必要な前提が揃う通常作業は連続実行する。結果を左右する重要な業務判断・権限・アクセス不足だけを具体的に確認し、それに依存しない作業は続ける。
- 案件単位で前提を判定する。目標14案件がすべて揃うまで、準備済み案件の設計・開発を止めない。数を合わせるための架空案件を作らない。
- 正式要求、今回の対応一覧、現行設計、歴史参考を区別する。参考Source Diffを今回の正式仕様の代わりにしない。
- 重要結論に実ファイル・版・行／章／シート等の位置を付ける。事実、推測、未読、アクセス不能、未確認、不適用を区別し、不適用には理由を残す。
- 会社工程の既存成果ディレクトリを優先する。決まりがなければ `調査結果/追加開発/<実際の実行日時>/<確認済み案件ID>/<チケットID>/` を使う。案件IDが不明な間は架空の対象を作らない。

- 実際の完了条件を満たしてからIssueを終了する。コピー、スクリプト成功、用例生成、Source保存だけで調査や試験全体の完了としない。
