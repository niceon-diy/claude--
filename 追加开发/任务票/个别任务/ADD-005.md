### 目的

确认设计要求原本是否体现在既有对应一览中，形成可追溯的核对版。

### 前置任务

- [ADD-001｜建立公司工程、追加项目、资料及 Source 基准索引](https://github.com/niceon-diy/claude--/issues/1)

### 输入

- Word 基本设计书、有效版本及目标范围
- 补列前的追加对应一览和原行 ID

### 实际执行步骤

1. 保存原文件、行列、顺序、内容及版本／指纹。有效修订或版本不明确时列待确认。
2. 盘点章、节、正文、表格、合并单元格、续表、图、文本框和附录，并记录无法读取对象的位置；不推测填写页码或自动编号。
3. 为可独立判断的要求分配设计项 ID，保留条件、正常、异常和边界的原文位置，展开与原表行的多对多关系。
4. 只以补列前原有内容判断完整覆盖／部分覆盖／未覆盖／待确认／不适用，不把后来新增的引用当作原先已覆盖的证据。
5. 在新核对版的原列右侧追加设计章节、具体原文、逐项结果、差异与原表依据、原文位置。没有对应行的设计项单列，不强塞到既有行。
6. 核对设计项 ID、行 ID、状态、统计关系和原单元格保持情况，实际打开检查长文本、换行、错列和截断。

### 成果物

- 保留原内容的对应一览核对版
- 全量设计项台账、多对多映射、未覆盖／待确认／未读对象明细

### 完成条件

- [ ] 没有以新增引用制造原先已覆盖的表象
- [ ] 要求数与状态数一致，不把关联行数当要求数
- [ ] 存在未解析部分时没有宣称已全量确认

### 缺失或失败时

保存缺失项、实际已检查范围、受影响结论／对象、确认人或资料及最短补充方式，并继续可独立完成的工作。重要规格矛盾不能擅自消解；没有执行、没有生成或没有测试的内容不得报告完成。

業務状態：未着手（会社工程で実行前）

### 目的

設計要求が既存の対応一覧に本来含まれていたかを確認し、追跡できる確認版を作る。

### 前提チケット

- [ADD-001｜会社工程・追加案件・資料・Source基準の索引を作る](https://github.com/niceon-diy/claude--/issues/1)

各実案件について必要な成果が揃うか、不適用の根拠があるかを判定する。前提チケットの全案件が一斉に完了するまで待つ意味ではない。

### 入力

- Word基本設計書と有効版・対象範囲
- 補列前の追加対応一覧と原行ID

### 実際に行う手順

1. 原ファイル、行・列・順序・内容と版／指紋を保存する。有効な変更履歴や版が不明なら確認事項にする。
2. 章、節、本文、表、結合セル、続表、図、テキストボックス、付録を棚卸しし、読めない対象の位置も残す。頁番号や自動番号を推測で埋めない。
3. 独立判断できる要求に設計項IDを付け、条件・正常・例外・境界を保った原文位置を登録する。元の行との多対多関係を明細化する。
4. 補列前の元内容だけを根拠に完全／部分／未カバー／待確認／不適用を判定する。追加した引用文を元から対応済みだった証拠にしない。
5. 新しい確認版の元列右側へ、設計章節、具体原文、項目別結果、差異と元表の根拠、原文位置を追加する。未対応設計は無理に既存行へ入れず別一覧にする。
6. 設計項IDと行ID、状態、集計の整合性、元セル保持を確認し、実際に開いて長文・改行・列ずれ・切捨てを点検する。

### 成果物

- 原内容を保持した対応一覧確認版
- 設計項全量台帳、多対多対応、未カバー・待確認・未読対象の明細

### 完了条件

- [ ] 新規引用による見掛けのカバーをしていない
- [ ] 要求数と状態数が整合し、対応行数を要求数に数えていない
- [ ] 未解析部分があれば全量確認済みと宣言していない

### 不足・失敗時

不足項、実際に調べた範囲、影響する結論／対象、確認先・資料と最短の補充方法を保存し、独立して進められる作業は続ける。重要な仕様矛盾を勝手に解消せず、未実行・未生成・未試験の内容を完了と報告しない。
