# 基本设计书覆盖核对和对应一览补列

用途：核对 Word 基本设计书中的每条相关设计要求，是否已经体现在原来的对应一览中；再把章节、具体内容和核对结果补到相应行右侧。

这是给公司 Claude Code 的任务定义，尚未对公司资料执行核对。填写下面路径和范围后，将正文发送给 Claude。

请对 Word 基本设计书与现有对应一览进行逐项覆盖核对，并输出在原一览右侧追加设计依据的核对版。

- Word 基本设计书路径及版本：<填写，版本无法确认时标明>
- 原对应一览路径：<填写>
- 本次过去项目及追加范围：<填写已知信息，未明确的范围列待确认>
- 成果保存位置：<沿用当前工程调查成果位置>

## 核对基准

先保留两份输入的版本或指纹，以及原对应一览的行标识、行序、原有列和内容。核对结论必须以补列前的原始一览为依据；新追加的设计原文只是追溯说明，不能算作原来已经覆盖。

本轮输出新的核对版，原始设计书和原对应一览保持原样。不要为消除差异而改写原有内容、删行或将设计内容强行归到相似项目中。

## 先完整盘点 Word

1. 确认实际格式和版本。旧 `.doc` 在保留原件的前提下用可用工具转换；无法可靠转换时报告缺口。修订、批注或多个版本导致当前有效正文不明确时列待确认，不擅自接受或删除修订。
2. 按原文顺序盘点章、节、子项、正文、表格、附录及相关注释。自动编号不能只凭导出的纯文本猜测；表格要覆盖合并单元格、跨页续表和其中各条要求。
3. 检查图、流程图、文本框及嵌入对象中的相关设计内容。无法可靠提取或看清的部分记录原位置和待确认事项；不能直接忽略后宣布全文完整。
4. 对照原文或渲染页面核查盘点范围。页码只有核实过才能填写；主要定位同时保留章节路径、段落序号或表格行列。

## 逐条建立设计项与原表行的关系

- 最小核对单位是一条可独立判断的设计要求，分配唯一设计项 ID；保留完整章节路径、相关原文和定位依据。正常处理、触发条件、输入输出、异常及边界分支分别核对。
- 沿用原一览行 ID；没有稳定 ID 时，在核对明细中建立与原始行号及原有内容相连的行 ID，不改动原表已有编号。
- 一个设计项可以对应多行，一行也可以关联多个设计项。每条映射记录设计项 ID、原表行 ID、原表已有依据及覆盖理由，避免用章节名或关键词命中代替判断。
- 覆盖判断基于原表原有内容是否体现该条要求对应的工作对象、处理和必要条件。无法确认含义等价时标为待确认；只体现部分要求时标为部分覆盖。
- 一个设计项只有在全部必要要求由关联的原表行共同完整体现，且没有未确认部分时，才能判为全局完整覆盖。不能因为其中一条关联成立或关联行数多，就认定整项完整覆盖。
- Word 全部章、节、项先纳入盘点。确属本次追加范围以外的内容，须记录依据和不适用理由；范围不明时标为待确认。纯标题和结构说明单独登记，不混入具体设计要求计数。
- 找不到相应原表行的设计项，进入未覆盖或待确认清单，不能为了完成补列而硬塞到相似行。

## 在原有列右侧追加

原有行序、编号、列和内容保持不变。右侧按以下字段补充：

| 新增列 | 填写要求 |
| --- | --- |
| 对应设计书章节 | 设计项 ID、完整章／节／项编号及标题；编号未核实则注明 |
| 设计书具体内容 | 相关原文中的具体要求，保留主体、条件、处理、结果和异常，不能只填标题或关键词；归纳说明另行标明 |
| 核对结果 | 完整覆盖／部分覆盖／待确认，按设计项分别列明；没有设计依据时写“待确认（未找到设计依据）” |
| 差异与覆盖依据 | 引用原表原有列和原文，说明已经体现什么、还缺什么及判断理由 |
| Word 原文定位 | 文件与版本、章节路径、段落或表格行列；页码如已核实可补充 |

一行关联多条设计项时，按设计项 ID 分条填写，保持每条的章节、原文、判断和依据相互对应。长内容应换行，不能用一个模糊的总体结论代替各条判断。

若未找到某个原表项目的设计依据，说明此次搜索范围并标为待确认，不直接判断该原表项目有误，也不编造章节补齐。

## 输出和验收

请交付：

1. **对应一览核对版**：在原表右侧新增上述列，保留原有内容和格式；长文本可读。
2. **全量设计项核对明细**：每条设计要求只保留一个全局状态，关联一行或多行的映射另行记录。全局状态为完整覆盖、部分覆盖、未覆盖、待确认、不适用；不适用必须有理由。
3. **未覆盖及待确认事项清单**：包括没有可对应原行的设计项、无法可靠读取的内容、版本或范围疑问，并给出原文定位。

用脚本核对设计项 ID 唯一性、状态是否齐全、映射的设计项与原表行是否存在、原有行和单元格是否保持，以及：

`设计要求总数 = 完整覆盖 + 部分覆盖 + 未覆盖 + 待确认 + 不适用`

多对多映射的关联条数不能当作设计要求数。结构计数通过只证明登记和关联自洽，不能证明 Word 提取或语义判断正确。

仍有无法可靠读取的内容时，只报告已识别设计要求数和未解析对象清单，不能把局部计数当作全文总数或宣称全文完整覆盖。

再从 Word 原文反向检查各条设计要求和对应行，重点核实条件、异常、边界及表格内容。重新打开核对版，确认追加列、换行和长文本没有错位、截断或丢失；无法实际查看的部分如实说明。

最后用约 10 行说明：核对版本与范围、盘点章节和设计项数量、各状态数量、没有对应行的数量、无法可靠读取的内容、原表保持检查、实际验证及结果、成果位置和下一步。仍有未确认项时报告剩余问题，不宣称全部无遗漏。
