## 中文

### 1. 目标、对象与实际范围

核心场景是批处理异常结束后，**从 Shell／Job 开头重新执行**，检查是否重复登记、错误更新、覆盖／删除／移动必要文件，或重复执行 PCO、共通例程和其他程序产生副作用。实际运用还允许从中途或检查点恢复时，分别定义恢复单位与前提，不能与从头重运行混为一谈。

输入包括目标 Shell／Job／JCL 与版本、调用的业务 Source、配置及参数、输入输出文件、DB 更新和事务／提交／检查点，以及公司的再执行和恢复步骤。范围包括本次追加影响的相关程序和外部依赖，不强行扩展到无关的所有批处理。

本清单支持调查并保存成果。读取 Source／SQL 只形成静态证据，不等于已经运行程序、实测 DB 或证明可以安全重运行。必要的运行验证只在当前任务许可的测试环境、数据和操作范围内执行；未获相应授权不执行程序或数据库操作。

### 2. 追踪调用、动态值和副作用

| 检查对象 | 需要查清并保留的依据 |
| --- | --- |
| 调用链 | Shell 直接调用、被调用方继续调用、PCO 程序、共通例程及其他程序；记录调用处、目标、条件、重要实参、返回值／结束码、执行顺序和异常出口 |
| 动态目标 | 变量赋值、拼接、替换、环境值和参数来源如何决定程序名、文件名、完整路径及 SQL 参数；记录能确定的值／候选和条件，不能唯一确定时保持未解决 |
| 间接与条件调用 | 包装脚本、间接／动态调用、分支和循环；查明什么时候调用、调用几次、失败如何传递，不能靠简单文本搜索就宣布全部调用已确定 |
| SQL 与事务 | 实际 SQL、对象、WHERE／其他执行条件、参数、插入／更新／删除及读写影响；提交、回退、自动提交、事务边界和异常后已持久化的部分 |
| 文件 | 读取、创建、写入、追加、覆盖、删除、移动、重命名、临时及中间文件；位置、存在条件、原内容、完成标志以及异常后是否仍可再次作为输入 |
| 外部副作用 | DB 之外的 IF、外部系统发送、输出交付、共通资源等；外部操作是否已经完成、能否撤回、重复执行会发生什么，证据缺少时标明 |
| 并行与依赖状态 | 上下游、共通部件、必要文件／DB 状态及实际相关的排他／并行条件；说明恢复时需要哪些依赖状态，未调查部分单列 |

同一个程序被多条路径调用时，按实际路径和条件分别记录。只有名字相同不能认定参数、数据和副作用相同；代码里未出现风险描述也不能推断没有风险。

### 3. 按异常位置确认残留状态与恢复

对每个相关阶段的异常出口或有代表性的中断点，建立以下矩阵：

| 阶段／异常位置 | 已执行的程序与操作 | DB／文件／外部残留状态 | 重复执行风险 | 必要恢复／清理 | 再执行入口与单位 | 成立前提／限制 | 依据与验证状态 |
| --- | --- | --- | --- | --- | --- | --- | --- |

逐项确认：

1. 哪些数据或文件已产生、已提交、部分更新、已交付或已删除，哪些仍未完成；不能把程序结束码直接等同于全部回退。
2. 从开头重新执行会否重复 INSERT／追加输出、错误 UPDATE、重复外部发送、丢失输入、覆盖必要成果、违反处理顺序，或者重复调用共通处理。
3. 是否需要恢复 DB／文件、移除部分成果、重新准备输入、重置检查点／完成标志；写明具体对象、恢复依据、负责步骤及适用顺序，不猜测可以直接清理。
4. 可以从哪个 Shell／Job／程序／检查点开始，为什么该入口成立，以及输入、版本、日期／参数、上下游和外部系统必须满足什么条件。
5. 无法还原或无法确认的状态会影响哪个判断；必要资料缺失时记录确认对象和最短补充方法，继续不依赖该缺口的调查。

### 4. 验证、证据冲突和判定

- 对需要实测的部分，依据实际改修和风险准备正常、异常中断、部分提交、重复执行、恢复后执行等适用场景；预期数据／文件／外部状态和比较方法事先给出依据，不把测试程序的输出当成唯一预期值。
- 只在已许可的测试范围实际执行，记录环境、版本、输入／参数、命令、执行前后状态、实际结果、失败和限制。不能执行的场景列为未验证，不伪造命令或结果。
- 每条发现标为“已确认／推测／未确认／证据冲突”。冲突时同时保留代码、设计、运用或实测的来源与具体差异，指出影响的结论；未解决前不能选择有利证据宣布可重运行。
- 调用目标未解、必要 Source 未读、事务／外部副作用未确认或恢复前提缺失时，不能给出整个批处理无条件可重运行的结论。没有发现风险、脚本通过或少数场景成功都不能证明全部安全。
- 逐个恢复单位给出“在列明前提下可重运行／需要恢复后才能重运行／不可重运行／尚未确认”的结论，并区分静态依据与实际运行验证。静态判断没有经过运行验证时，明确写出这个限制。
- 最终从结论反查实际 Source、调用路径、动态参数和残留／恢复证据，确认推测没有在后续步骤变成事实。不能以 AI 自称已检查代替复查。

### 5. 成果与完成检查

沿用既有调查成果位置，保存目标及版本范围、调用边与参数表、未解析目标、证据索引、异常位置矩阵、恢复／再执行步骤及限制、必要测试场景和实际执行证据（如已执行）。测试场景可衔接 [ADD-012：连接测试](https://github.com/niceon-diy/claude--/issues/13)，不能把仅生成场景写成测试完成。

- [ ] 已追踪必要的直接、间接、动态和条件调用；无法确定的目标有记录。
- [ ] 程序、文件、DB、外部系统的实际副作用及异常残留有依据。
- [ ] 各恢复单位的入口、前提、恢复方法、顺序和重复风险已说明。
- [ ] 已确认、推测、未确认、冲突、未验证和不适用均明确，不适用有理由。
- [ ] 必要实测的已执行结果和未执行部分分开；没有仅看部分 Source 就认定整体安全。
- [ ] 结论能回到真实 Source／配置／运用或测试证据；交接说明成果完整路径、限制和下一步。

## 日本語

### 1. 目的・対象・実際の範囲

中心となるのは、バッチが異常終了した後に **Shell／Job 全体を先頭から再実行する**場面です。二重登録、不正更新、必要ファイルの上書き・削除・移動、PCO・共通ルーチン・その他プログラムの再実行による副作用を確認します。途中やチェックポイントからの再開も実運用で認める場合は、復旧単位と前提を別に定め、先頭からのリランと混同しません。

入力は、対象 Shell／Job／JCL と版、呼出す業務 Source、設定・引数、入出力ファイル、DB 更新・トランザクション・コミット・チェックポイント、会社の再実行／復旧手順です。今回追加が影響する関連プログラムと外部依存を対象にし、無関係な全バッチへ機械的に広げません。

本チェックリストは調査と成果保存に使います。Source・SQL の読取りは静的根拠であり、プログラム実行、DB 実測、リラン安全性の実証ではありません。必要な動作確認は現タスクで認められた試験環境・データ・操作範囲に限ります。対応する許可がなければプログラム実行や DB 操作を行いません。

### 2. 呼出し・動的値・副作用を追う

| 確認対象 | 明らかにし、根拠を残す内容 |
| --- | --- |
| 呼出しチェーン | Shell の直接呼出し、呼出し先からの追加呼出し、PCO、共通ルーチン等。呼出し位置、対象、条件、重要引数、戻り値／終了コード、順序、異常出口 |
| 動的な対象 | 変数の代入・連結・置換、環境値、引数の出所からプログラム名、ファイル名、絶対パス、SQL パラメータがどう決まるか。確定値・候補と条件を示し、一意に決まらなければ未解決とする |
| 間接・条件呼出し | ラッパースクリプト、間接・動的呼出し、分岐、ループ。呼ぶ条件・回数・失敗の伝播を確認し、単純な文字検索で全呼出しが特定できたとしない |
| SQL とトランザクション | 実 SQL、対象、WHERE 等の条件、引数、INSERT／UPDATE／DELETE と参照更新の影響。コミット、ロールバック、自動コミット、トランザクション境界、異常後の永続化部分 |
| ファイル | 読取、作成、書込、追記、上書き、削除、移動、改名、一時・中間ファイル。場所、存在条件、元内容、完了標識、異常後に再び入力として使えるか |
| 外部副作用 | DB 以外の IF、外部送信、出力の引渡し、共有資源。外部処理が完了済みか、取消可能か、重複実行の結果。不足する根拠を明示する |
| 並行・依存状態 | 上下流、共通部品、必要ファイル／DB 状態、実際に関係する排他・並行条件。復旧で必要な依存状態と未調査部分 |

同じプログラムでも、実経路と条件ごとに記録します。同名だから引数・データ・副作用も同じとは判断しません。コードに危険の説明がないことから、危険なしと推定しません。

### 3. 異常位置ごとの残留と復旧を確認する

各関連段階の異常出口や代表的な中断点について、次の表を作ります。

| 段階／異常位置 | 実行済みプログラム・操作 | DB／ファイル／外部の残留状態 | 重複実行リスク | 必要な復旧・クリーンアップ | 再実行入口・単位 | 前提・制限 | 根拠・検証状態 |
| --- | --- | --- | --- | --- | --- | --- | --- |

次を個別に確認します。

1. 作成済み、コミット済み、部分更新、引渡し済み、削除済み、未完了のデータ・ファイルを分けます。終了コードを全体ロールバックと同一視しません。
2. 先頭から実行すると二重 INSERT・追記、不正 UPDATE、重複送信、入力喪失、必要成果の上書き、順序違反、共通処理の二重実行が起こるかを調べます。
3. DB／ファイル復元、部分成果の除去、入力の再準備、チェックポイント／完了標識のリセットが必要かを調べます。対象、復旧根拠、担当手順、順序を示し、直ちにクリーンアップできると推測しません。
4. どの Shell／Job／プログラム／チェックポイントから開始できるか、その根拠、入力・版・日付／引数・上下流・外部システムの必要状態を示します。
5. 復元不能・未確認状態がどの判断に影響するかを示します。資料不足は確認先と最短の補充方法を記録し、不足に依存しない調査は続けます。

### 4. 検証・証拠の不整合・判定

- 実測が必要な部分は、実改修とリスクに応じて正常、異常中断、部分コミット、重複実行、復旧後実行等を用意します。期待するデータ・ファイル・外部状態と比較方法に事前の根拠を付け、試験対象の出力だけを期待値にしません。
- 許可済みの試験範囲で実行し、環境、版、入力・引数、コマンド、前後状態、実結果、失敗、制限を残します。未実行は未検証とし、コマンドや結果を作りません。
- 各発見を「確認済み／推測／未確認／証拠の不整合」に分けます。不整合ではコード・設計・運用・実測の双方の出所と差異、影響する結論を残し、解消前に都合のよい根拠だけでリラン可能としません。
- 呼出し先が未解決、必要 Source が未読、トランザクション・外部副作用が未確認、復旧前提が不足する場合、バッチ全体を無条件で再実行可能としません。危険未発見、スクリプト成功、少数シナリオ成功は全体の安全証明ではありません。
- 復旧単位ごとに「明記した前提でリラン可能／復旧後に可能／リラン不可／未確認」とし、静的根拠と実動作検証を区別します。静的判断に実行確認がなければ、その制限を明記します。
- 最後に結論から実 Source、呼出し経路、動的引数、残留・復旧根拠を逆照合し、推測が後段で事実になっていないか確認します。AI の確認済みという申告を再点検の代わりにしません。

### 5. 成果と完了チェック

既存成果場所に、対象・版・範囲、呼出し辺・引数表、未解決対象、根拠索引、異常位置の表、復旧・再実行手順と制限、必要試験と実行証拠（実施済みの場合）を保存します。試験は [ADD-012：接続試験](https://github.com/niceon-diy/claude--/issues/13)へ関連付けられますが、シナリオ作成だけで試験完了にしません。

- [ ] 必要な直接・間接・動的・条件呼出しを追い、不明な対象を記録した。
- [ ] プログラム、ファイル、DB、外部システムの実副作用と異常残留に根拠がある。
- [ ] 復旧単位ごとに入口、前提、復旧方法、順序、重複リスクを説明した。
- [ ] 確認済み、推測、未確認、不整合、未検証、不適用を明記し、不適用に理由がある。
- [ ] 必要な実測の実施結果と未実施を分け、一部 Source だけで全体を安全としていない。
- [ ] 結論から実 Source・設定・運用・試験へ戻れ、引継ぎに成果の絶対パス、制限、次の作業がある。
