## 本パックの納品確認

1. P003 の本文は単独で利用でき、旧調査プロンプトや全タスク票を同時に送る必要はありません。他のファイルは利用と確認のための補助資料です。
2. 中国語原版では構造確認済みです。本文の開始／終了マーカーは各一つ、00～17 の全18章、8組の主要要件と8つの質問番号、当時の本パックと入口の13か所の相対リンク、コードブロックの対応を確認しています。2026-11-12の日本語追補では、中日両本文の全18章について、小見出し、箇条書き、番号付き手順、表の行、コードブロックの数がすべて一致し、8つのQIDも対応することを確認済みです。現在の中日実行パック内の25か所の内部リンクも確認済みです。
3. データスクリプト生成と実際の投入を区別し、投入は目標構造が整った後に実行します。デプロイと DDL の順序は依存計画に従います。
4. Source 改修後は対応するコンパイル済み成果物を取得し、旧プログラムを使って新改修が合格したと証明しません。
5. 期待結果の根拠を独立させ、原値と証拠を保持します。実際の結果に合わせた期待結果の変更、難しい Case の削除、無視範囲の拡大は行いません。
6. FTP の転送成功をリモート実行の証明とせず、Oracle DDL とテストデータのトランザクションを分離します。結果不明の場合は実環境の状態を先に確認してから復旧します。
7. 問答テンプレートには汎用的な質問と空の回答欄だけを含み、会社のアカウント、実環境の値、業務データ、認証情報は含めません。
8. 公開は GitHub の現行既定ブランチ `codex/claude-environment` の実ファイルと最新コミットを基準に行い、他のリモート内容は保持します。本パックと関連入口／旧段階の説明だけを対象とし、他のローカル未コミット資料は一緒に含めません。

中国語原版では二回の独立内容レビューの修正を反映しています。旧タスク制限を置き換える宣言をコピー対象本文内に含め、Case ごとの前提確認、後片付け前の証拠保存、マイグレーション ID／ハッシュの衝突、期待結果不足時の収集のみの実行範囲、問答の正本の状態を明確にしています。日本語版もこれらの要求を保持します。公開後は、リモートファイルの内容とコミット対象ファイル一覧を再読し、ローカルとの一致を確認します。

日本語版は三つの範囲に分担して翻訳し、別担当による相互照合を実施しました。「接续记录」は引き継ぎ・再開用の記録とし、「前台 PL → 前台 BL → batch」などのプロジェクト用語は独断で技術分類に置き換えず原語を保持しています。中国語の実行本文の要求は変更していません。
