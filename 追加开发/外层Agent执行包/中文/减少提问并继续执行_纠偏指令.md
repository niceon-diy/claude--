# 减少提问并继续执行：当前会话纠偏指令

2026-11-12（日本时间），P003 v1.1 补充。

只把下面指令发给当前 Claude 会话，继续原任务；不必重开会话、重发整份提示词或从头重跑工程。

请不要把现有问题全部答完作为开工条件。先读取已有成果、运行记录、回答、配置和代码，从实际状态继续。已可查明的事项附依据自行解决，重复问题合并；原8项是调查分类，不是用户必须填写的问卷。

## 先整理问题

将现有问题分成四类：

1. **可以自行查证**：查工程、Manual、配置、代码和日志，记录依据后继续。
2. **可回退的技术选择**：优先沿用现有接口、目录、命名、输出格式和Framework默认，采用最小改动，记录技术假设及回退方式后执行。
3. **不阻塞当前工作的事项**：保留在权威记录中，注明影响与何时再检查，不停止当前工作。
4. **真正需要用户决定**：资料不能确定的业务规则、固定想定、范围或实际权限，仅暂停依赖它的操作，继续其余工作。

当前请用户处理的决策最多3项，每项只写“一句话问题／已查依据／建议／回答前仍可做的下一步”。其余真实问题保留追踪，不隐瞒、不丢弃；数量限制不表示可忽略风险或将未回答视为批准。不得靠分成多轮连续提问来绕过这个限制。

已有数据、固定想定和业务规则不得猜测，不能按实际输出改想定。生产、共享／他人对象、破坏性操作及真实权限不足仍按原边界处理，不扩大权限，不绕过平台强制审批。

## 这轮先交什么

先完成一个已确认对象的**外层入口 → 调用一个既存Agent → 保存原始输出 → 做一项实际检查**，提供运行方式和证据。已有这条链就继续其余就绪范围；不要只交改名Agent、空适配器或计划书。

FTP、Oracle连接或目标定义缺失，只暂缓对应远端应用。继续输入适配、既有Agent接入、检查器、部署／迁移计划、数据脚本和离线检查。无真实输入或调用条件时如实标离线验证，不能把虚构样例当远端部署、DB更新或业务通过的证明。

不要在普通节点以“请确认后继续”结束。只有全部可做的工作都已完成、剩余工作确实被必要缺口卡住时，才把最小缺口集中提出，并保存实际成果、剩余范围、依据和恢复点。
