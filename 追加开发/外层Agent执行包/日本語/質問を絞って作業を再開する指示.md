# 質問を絞って作業を再開する指示

2026-11-12（日本時間）・P003 v1.1 補足

この指示だけを現在の Claude 会話に送り、元のタスクを続けてください。新しい会話への切替え、全文の再送、プロジェクト全体の最初からの再実行は不要です。

今の質問一覧をすべて埋めることを着手条件にせず、既存成果、実行記録、回答、設定、コードを読み、実際の状態から再開してください。既に確認できた事項は根拠を付けて解決済みとし、重複質問をまとめてください。事前確認の8項目は調査用であり、ユーザーの必須回答票ではありません。

## 質問の整理

各質問を次の四つに分類してください。

1. **自分で確認できる事項**：工程、Manual、設定、既存コード・ログから調べ、根拠を記録して進める。
2. **元に戻せる技術上の選択**：既存のインターフェース、ディレクトリ、命名、出力形式、Framework の技術的な既定値を優先する。変更を最小限にし、採用した仮定と戻し方を記録して実施する。
3. **今の作業を妨げない事項**：質問の正本に残し、影響範囲と見直す時点を付ける。現在の作業は止めない。
4. **ユーザーの判断が本当に必要な事項**：調査で決められない業務仕様、固定された期待結果、対象範囲や実際の権限など。依存する操作だけを保留し、他の作業を進める。

今すぐユーザーに求める判断は、実際に現在の作業を止めているものから**最大3件**に絞ってください。各件は「一文の質問／調査済みの証拠／推奨案／回答までに進める次の作業」で示してください。他の実在する問題も正本で追跡し、隠したり捨てたりしないでください。件数制限はリスクの無視や、無回答を承認とみなす理由にはなりません。3件ずつ何ラウンドも質問し続け、制限を回避しないでください。

既存データ、固定期待結果、業務ルールは推測で作らず、実結果に合わせて期待結果を変えないでください。本番、共有・他ユーザーの対象、破壊的操作、実際の権限不足は従来の境界を維持し、権限を拡大したり必須承認を回避したりしないでください。

## この実行で先に完成させること

確認済みの一対象について、**外側Agentの入口 → 既存Agentの実呼出し → 元の出力の保存 → 実際のチェック**までの、動作する最小の流れを完成させてください。既にある場合は有効性を確認し、準備が整った実対象へ続けてください。名前だけの Agent、空のアダプター、計画書だけで完了とせず、実際の成果と確認証拠をまず一つ提出してください。

FTP や Oracle の接続・定義が不足する場合は、必要な遠隔適用だけを保留してください。確認済みの範囲で入力適合、既存 Agent の接続、検査器、配備・移行計画、データスクリプト、オフラインチェックを進めます。仮想データの検証と実環境の実行を区別し、未実施の配備、DB 更新、業務テストを合格扱いにしないでください。

通常の区切りで「確認後に続行します」と待たず、確認→実施→検証→修正→次の作業を続けてください。保留は対象ごとに判断します。実行可能な作業をすべて終え、残る全作業が本当の不足に依存すると確認した時だけ、その最小の不足を一度に質問し、実成果、残件、証拠、再開点を保存してください。

まず既存の質問を分類し直し、確認済みの対象で一つの実成果を完成させてください。元のタスクの目標と有効な権限・検証条件は維持します。
