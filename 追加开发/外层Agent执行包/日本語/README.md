# 会社の Claude 向け：外側 Agent 完全実行パック

日本語版追補日：2026-11-12（日本時間）。中国語原版の整理日：2026-11-11、P003 v1.0。実際の実装・実行に用いるパックであり、従来の「要件分析だけを行い、回答後に確認を待つ」段階に代わるものです。

**そのまま利用する文書：[P003 完全実行プロンプト・日本語版](P003_外側Agentによる設計開発テスト全工程実行プロンプト.md)。**

**中国語版と日本語版は、同じタスクの完全版です。どちらか一方を選び、一度だけ実行してください。** 両方を順番に送信して、デプロイ・データ更新・テストを重複実行しないでください。各言語は別ディレクトリに保存し、このディレクトリには日本語の完全プロンプト、利用案内、質問・回答テンプレート、確認表のみを置いています。

今回の要件は、自作の設計・開発・テスト用の外側 Agent が入力を処理し、既存 Framework Agent を呼び出し、実際の出力を検査して、根拠に基づく補完または対象を絞った手戻りを行うことです。テストでは既存の能力をできる限り再利用し、Matrix／固定 Case／期待結果（想定）→ データ準備 → プログラムと Oracle の環境整備 → 実行 → 結果取得 → 比較を接続します。質問はファイルに集約し、それ以外の作業を継続します。

## 最も簡単な利用方法

1. 会社の端末で本パックを取得し、実際の業務プロジェクトで Claude を開きます。
2. 下記の起動指示のパスを、会社側のコピーにある P003 の実際の絶対パスに置き換え、一度送信します。
3. Claude が本パックのファイルを読めない場合は、P003 の「プロンプト開始」から「プロンプト終了」までの全文をそのままコピーして送信します。

```text
次のファイルに含まれるタスク本文全体を読み、実行してください。
【会社の端末にある P003_外側Agentによる設計開発テスト全工程実行プロンプト.md の絶対パス】

これは要件分析だけではなく、実際の実装・実行タスクです。現在の会社の実業務プロジェクトを対象に、
私の設計・開発・テスト用の外側 Agent を実装し、既存 Framework の Agent とツールを優先的に呼び出し、
入力処理、出力検査、根拠に基づく補完、および対象を絞った手戻りを実施してください。
テストは私の Matrix、固定 Case、期待結果を基準とし、個人開発環境における
プログラムのデプロイ、Oracle 構造更新、初期テーブルとテストデータ、実行、収集、比較を接続してください。
自分で調べられる情報は先に調べ、必要な質問は会社側ディレクトリ内の一つの問答ファイルに集約してください。
回答が必要なステップだけを保留し、回答に依存しない作業はすべて継続し、段階ごとに私の確認を待たないでください。
ファイルに示した権限、バージョン、検証、引継ぎのルールに従い、実際の状態から継続して実行してください。
```

最初にすべてのパス、アカウント、または八つの質問を記入する必要はありません。Claude が現在のプロジェクトと有効な設定を先に読み、本当に資料が不足している場合にファイルへ記録します。アカウントのパスワードは、プロンプト、問答ファイル、公開 Git に記載しません。

## 回答後の再開

会社側ディレクトリ内の問答ファイルに回答を記入した後、次を送信します。

```text
本プロジェクトの外側 Agent の最新実行記録と問答の正本を読み、私の追加回答を確認してください。
影響を受ける設計、Source、Case、データ、環境準備を更新し、関連する検証を実行してください。
実際の中断点から、実行条件がそろったすべてのタスクを再開してください。
残る質問は引き続き同じファイルへ集約し、段階ごとに確認を待たないでください。
```

## 旧資料との関係

- 従来の「自作簡素化 Agent の要件分析」は議論の履歴として残します。そこにある「開発しない、読み取り専用、ファイルを作成しない、回答後に待つ」は、今回のタスク全体を止める条件にはしません。
- P003 は外側 Agent から既存 Framework Agent を呼び出すことを認めています。内側の Agent をすべて書き直すことや、先に Framework 全体を再構築することを要求しません。
- 有効な会社ルール、実際の権限、プラットフォームの必須承認は引き続き適用します。個人開発範囲内で承認済みかつ条件が明確な通常作業は継続し、本当に範囲外の操作や業務判断を要する事項だけを個別に保留します。
- 本パックで作成済みなのはプロンプトと問答テンプレートです。会社の Framework、実際の Matrix、Source、コンパイル済み成果物、Oracle 開発環境は、会社側で読み取り、実装・実行・検証する必要があります。
