## 確認済みの要件

- 設計・開発・テストはすべて自作の外側 Agent を入口とし、入力処理、既存 Agent の呼出し、出力検査、根拠に基づく補完または対象を絞った手戻りを行います。
- 既存 Framework の Agent、ツール、フローが利用できる場合は優先的に再利用し、実際に不足する部分だけを補います。自作であることを理由に既存能力を書き直しません。
- データベースは Oracle で、コンパイル済み成果物があります。FTP は予定しているプログラム転送方式であり、実際の利用可否、ロード先ディレクトリ、反映方法は検証が必要です。
- 開発環境は個人の開発ユーザーごとに区分されています。Oracle の実際の接続ユーザー、schema、テーブルの owner、シノニムの参照先は、現場で確認する必要があります。
- テストはユーザー提供の Matrix、固定 Case、期待結果（想定）または判定ルールを根拠とし、Case 生成、データ準備、プログラムとデータベースの整備、初期テーブル、実行、結果収集、比較を対象とします。
- 質問はファイルへ集約して一括回答とし、通常の段階が終わるたびにユーザーを待ちません。一項目の不足で全作業を停止しません。
