# 程序清单比对

用途：对比过去项目的 Release 申请程序一览（A）与 Claude 的对应程序一览（B），找出需要核实的差异。

在公司直接把 [程序清单比对任务](程序清单比对任务.md) 发给 Claude Code，填写两份原文和工具仓库的路径即可。

## 能检查什么

- `release_only.csv`：A 有、B 没有，属于疑似漏列，需核实。
- `summary_only.csv`：B 有、A 没有，需核实范围、名称或发布情况。
- `matched.csv`：两份输入中程序标识相同，保留两侧的全部原始记录；相同程序数以报告中的唯一标识数为准，不能直接使用此表行数。
- `duplicates.csv`：同一标识的重复记录，保留每一条来源。
- `report.json`：输入指纹、记录数、唯一标识数、差异计数和核对结论。

这些结果只说明两份输入清单的差异。程序标识相同不代表版本相同；两份清单一致也不能证明原文提取完整、Release 范围完整，或设计书与影响分析完整。

## 输入要求

公司 Claude 先用脚本从文本、Markdown 提取两份 CSV，分别保留原文与提取脚本。每条记录必须至少包含：

```csv
program_id,source_ref
src/batch/ABC001.cbl,原Release申请.md 第18行
```

- `program_id`：原文中的完整程序标识，保留目录、大小写和扩展名。
- `source_ref`：能回到原文的文件名及行号，不能只指向转换后的 CSV。
- CSV 默认 UTF-8，可含 BOM；其他编码须显式指定。
- 两份输入均须有有效程序记录；空清单会报错，需先确认是实际无对象还是提取失败。
- 原文中无法判定的行、名称或对象类型，另列待确认。检查全部相关章节、表格和发布批次，核对原文候选记录数与导出记录数。
- 核对续行、一行多个程序及各行的处理去向，保留“已提取 / 非程序内容 / 待确认”的定位记录。两份 CSV 数量自洽不能证明原文提取完整。
- 工具只清除程序标识首尾空白；名称别名、源码与发布生成物之间的映射，需另给实际依据，不能自动猜测。
- 原文只给短名时，先确认能否唯一定位程序；存在同名对象或定位不明时，标识相同也应列为待确认。

## 运行

需要 Python 3.7 或以上，使用标准库。终端命令示例（路径按公司实际情况填写）：

```text
python compare_inventory.py --release release.csv --summary summary.csv --output comparison-run-001
```

指定编码的示例：

```text
python compare_inventory.py --release release.csv --release-encoding cp932 --summary summary.csv --output comparison-run-002
```

输出目录必须是新目录。重复运行请换一个输出目录，保留前后两次结果以便核对。

退出码：`0` 表示两份输入在当前标识规则下一致且没有重复；`1` 表示存在差异或重复，须核实；`2` 表示输入或运行错误。退出码 `0` 不等于整个项目“无遗漏”。

## 最后如何验收

1. 原文提取有来源、记录数能核对，无法判定内容有待确认记录。
2. 实际运行提供的脚本，保留命令、退出码与输出文件。
3. 唯一标识计数满足：`A = 相同 + A独有`，`B = 相同 + B独有`；原始重复记录另行列出。
4. 每个差异回到原资料或程序核实，写明“确认漏列 / 名称或对象映射 / 范围差异 / 待确认”及依据。
5. 拍照反馈中说明实际检查范围、差异数量和剩余问题，不把“工具通过”写成业务全面正确。

本地验证：Python 3.12.14 下 21 项测试通过；其他 Python 版本尚未运行验证。工具尚未接触公司原文，真实资料的提取与业务结论仍需在公司核对。
