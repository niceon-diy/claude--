# 项目追加注意事项

整理日期：2026-11-01

本文件记录项目追加时需要准备的 Input、追加对应一览的确认事项，以及 Source 开发所依据的资料。实际项目的路径、Thema ID、Source 和 Object 内容由具体项目填写。

## 1. Input：项目追加所需资料

| 输入项 | 需要提供的内容 | 用途 |
| --- | --- | --- |
| Source 源头 | 本次开发所基于的 Source 来源及位置 | 确定开发使用的 Source 基础 |
| 本番设计书的位置 | 现行本番设计书的存放位置 | 查阅现行设计内容 |
| Thema ID 和名称 | 本次追加对应的 Thema ID、名称 | 识别本次 Thema，并用于建立新 Thema 的 Box |
| 追加对应一览（核心） | 本次需要追加、修改的项目及具体对应内容 | 明确本次要做什么，作为 Source 开发的主要依据 |
| 过去参考 Thema 的位置 | 可参考的过去 Thema 及其资料位置 | 查阅过去的对应资料 |
| 过去参考 Thema 的 Source 改修位置 | 过去 Thema 中具体修改过的 Source 及其改修位置 | 为本次 Source 开发提供参考 |
| 外部设计（按需提供） | 尤其是新增项目的说明、具体设计内容 | 补充新增项目的详细要求 |

### 新 Thema Box 的建立

根据 **Source 源头、本番设计书的位置、Thema ID 和名称**等基础信息建立新 Thema 的 Box。

新 Thema Box 是接收基础信息后建立的资料容器，不作为独立的 Input 字段。

## 2. 追加对应一览需要确认的内容

### 2.1 以参考 Thema 的发布模块一览检查 Source 漏项（最关键）

追加对应一览完成后，以参考 Thema 的 **リリースモジュール一覧（发布模块一览）**为正确资料和核对基准，检查对应一览中的 Source 是否存在遗漏。

确认时需要：

1. 找到参考 Thema 的リリースモジュール一覧。
2. 按其中列出的 Source，逐项核对追加对应一览。
3. 找出未列入追加对应一览的 Source，确认其与本次追加的关系；属于本次对应范围的，补入一览。
4. 对范围或对应关系尚不明确的项目，记录待确认内容。

本次新增的 Source，也要结合本次追加要求及外部设计确认并列入对应一览。

**重点：对应一览完成后必须回到参考 Thema 的リリースモジュール一覧检查，不能仅凭已经写出的对应一览判断没有漏项。**

### 2.2 调查每个 Source 的用途

对应一览中的每个 Source，都要调查清楚：

- 用在什么地方。
- 承担什么具体处理。
- 与本次追加或改修内容有什么关系。

例如，需要区分该 Source 是否用于**文件作成、DB 改修**等处理，并将调查结果记录到对应一览。不能只列 Source 名称而没有用途说明。

### 2.3 结合数据库 Object 一览和 DB 改修内容确认环境

需要准备并对照：

- **数据库的 Object 一览**。
- **DB 改修内容**。

据此确认：

1. 本次涉及哪些数据库 Object。
2. 哪些环境需要改修，例如**休日、LKN**等。
3. 各环境分别涉及哪些 Object。
4. 每个环境、每个 Object 具体需要修改什么内容。

环境范围应逐项确认，不能只写“需要 DB 改修”而没有说明对象、环境和具体内容。“休日”“LKN”沿用项目中的名称，其他环境按实际项目补充。

## 3. Source 开发的依据

Source 开发主要依据以下两项资料开展：

1. **追加对应一览**：说明本次要追加或修改什么。
2. **过去参考 Thema 的 Source 改修位置**：提供过去类似对应中具体改了哪里、如何改修的参考。

涉及新增项目时，同时结合**外部设计中的新增项目说明和具体设计内容**。

开发前，应先完成对应一览的 Source 漏项检查、用途调查，以及数据库 Object 和改修环境的确认。

## 4. 检查清单

- [ ] Source 源头、本番设计书位置、Thema ID 和名称已明确。
- [ ] 新 Thema 的 Box 已建立。
- [ ] 追加对应一览、过去参考 Thema 位置及其 Source 改修位置已准备。
- [ ] 已按需准备外部设计，并确认新增项目的说明和具体设计内容。
- [ ] 已以参考 Thema 的リリースモジュール一覧核对 Source 漏项。
- [ ] 每个 Source 的使用位置、处理用途及本次对应内容已调查并记录。
- [ ] 已结合数据库 Object 一览和 DB 改修内容确认改修对象。
- [ ] 已逐项确认休日、LKN 等实际涉及环境及各环境的具体改修内容。
- [ ] 尚未明确的范围、用途、Object 或环境已列为待确认事项。
