### 做了哪些整理

- 将原来的 70 个文件按用途映射，现用文件不再与旧资料、迁移快照混在根目录。
- 两个沿用 P002 编号的提示词分到“14 个项目核对”和“AI 智能体与 Manual 调查”目录，通过用途区分，保留历史编号。
- 任务票的 21 份单票、总任务与合并全文放在一起；生成器和唯一维护数据收进“维护”子目录。
- 同步任务数据的 22 个来源路径、生成文件、Markdown 导航及 GitHub Issue 中的资料链接。Issue 编号、标题、业务要求、依赖关系与业务状态保持原有内容。
- 首次接入提示词明确要求填写仓库内“开发环境”目录的绝对路径，确保能找到其下的“模板”。
- 历史原文与 JSON 快照保持原内容。历史记录中的路径表示记录当时的位置，现在位置见[目录映射.json](目录映射.json)；原始旧 Git 历史仍保存在原归档分支。

### 以后怎样维护

- 修改任务要求：编辑 `追加开发/任务票/维护/任务数据.json`；在仓库根目录运行 `python "追加开发/任务票/维护/生成任务票.py"`。生成器更新本地文件；需要发布到 GitHub 时仍须同步对应 Issue。
- 修改 AI 调查提示词：编辑 `通用提示词/AI智能体与Manual调查/P002_AI驱动开发工程智能体与Manual调查提示词.md`，再运行 `python "通用提示词/AI智能体与Manual调查/生成阅读版.py"`。
- 新增现用资料：放入对应用途目录，并更新该目录 README；历史原文放入历史归档，不再在多个目录手工维护相同内容。
- 查看完整旧／新路径：[目录映射.json](目录映射.json)。旧文件的固定版本可从整理前提交访问。

本次验证结果见[验证结果.json](验证结果.json)。资料整理与工具验证不代表公司项目已完成调查、开发或测试。
