## 中文：公司使用顺序

1. 在公司实际业务工程中打开 Claude，先确认已有工程规则和当前任务记录；本仓库是提示词与模板，不是公司实际业务 Source。
2. 优先把总任务 Issue 或“公司Claudeへ渡す_全チケット.md”的所需语言交给 Claude。先做追加案件与资料索引，再核对 Source 漏项、用途、参考差分、设计要求及 DB Object×环境范围。
3. 按有效的开发 Input 进行基本设计、详细设计、Source 开发、单体测试、连接测试和最终交接。已准备好的案件可以独立推进，不必等待全部14件资料齐备。
4. AI 智能体与 Manual 的仕組调查、Agent／Skill 架构讨论和新人 HTML 解说属于后续工作，不作为追加 Source 开发的前提。
5. 公司工程根目录、Source 基线、Thema、正式设计与成果保存位置由公司 Claude 从实际资料核实。不要把本地模板路径或历史任务的授权当作当前事实。
6. 实际公司资料和测试证据保存在公司内；公开 Issue 只记录不含公司敏感内容的进度、缺口及定位方法。发布模板不等于公司已执行、规则已加载、Source 已修改或测试已通过。

## 日本語：会社での使用順

1. 会社の実業務工程でClaudeを開き、既存の工程ルールと現在のタスク記録を確認します。このリポジトリはプロンプトとテンプレートであり、会社の業務Sourceそのものではありません。
2. 総合Issue、または「会社Claudeへ渡す_全チケット.md」の必要な言語版を優先して渡します。追加案件と資料の索引を作り、Source漏れ・用途・参考差分・設計要求・DB Object×環境を確認します。
3. 有効な開発Inputに従い、基本設計、詳細設計、Source開発、単体テスト、結合テスト、最終引継ぎへ進みます。準備済みの案件は独立して進められ、全14件の資料が揃うまで一律に待つ必要はありません。
4. AIエージェントとManualの仕組み調査、Agent／Skill構成の検討、初心者向けHTML解説は後続作業です。追加Source開発の前提にはしません。
5. 会社工程のルート、Source基準、Thema、正式設計、成果の保存場所は、会社Claudeが実資料から確認します。ローカルのテンプレートパスや過去タスクの権限を現在の事実とは扱いません。
6. 会社資料と試験証拠は会社内へ保存し、公開Issueには機密を含まない進捗・不足・確認方法だけを記録します。テンプレートの公開は、会社での実行、ルール読込み、Source改修、試験通過の証拠ではありません。
