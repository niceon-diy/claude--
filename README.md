# Claude Code 开发环境模板

这套文件帮助你用日常语言表达目标，让 Claude 整理任务、说明实际实现、核对成果，并保存下一次继续工作所需的信息。

## 在公司怎么用

1. 在公司通过 Git 获取本仓库。
2. 打开你实际工作的工程，并启动平时使用的 Claude Code。
3. 打开 [首次接入提示词.md](首次接入提示词.md)，填入本仓库在公司电脑上的路径，把其中的提示词发给 Claude。
4. Claude 检查现有工程规则，再合并必要内容，并给出简短的接入结果。

已有工程中的规则继续保留；只有影响接入的实际冲突需要你决定。

## 仓库里有什么

| 文件 | 用途 |
| --- | --- |
| [首次接入提示词.md](首次接入提示词.md) | 第一次接入时，复制给 Claude 的指令 |
| [模板/CLAUDE.md](模板/CLAUDE.md) | 项目协作总则：理解任务、调查实现、核对依据、保存进度 |
| [模板/当前任务.md](模板/当前任务.md) | 由 Claude 维护的任务与交接记录 |

## 平时怎么说需求

直接说目标、现有资料和最在意的结果。不清楚的地方让 Claude 帮你梳理，例如：

> 我想调查这次项目追加会影响哪些地方。历史类似项目的资料在……，当前最新版设计和程序在……。请先整理你的理解，输出修改对象、调用关系、依据和待确认事项。先选一个对象做出样例，让我看是否符合预期。

新会话可以说：

> 读取本工程的协作规则和当前任务记录，核对实际状态，告诉我现在进行到哪里，然后继续下一步。

## 怎么把结果反馈到这里

让公司 Claude 使用总则中的简短反馈格式，你可以拍下关键输出。反馈包含：当前阶段、已完成内容、验证结果、需要决定的问题和下一步。

这里根据反馈继续改进模板。需要核对代码或设计依据时，由公司 Claude 在公司工程内检查，再给出核对结果。

## 当前验证范围

本仓库已准备模板文件，尚未在公司实际工程中运行验证。首次接入后，选一个真实的小任务检查理解、证据、成果格式和会话交接是否符合预期。

CLAUDE.md 的加载方式见 [Claude Code 官方说明](https://code.claude.com/docs/en/memory)。接入后可按说明通过 `/context` 检查规则是否加载；文件中的协作要求仍需要结合实际成果核对。
