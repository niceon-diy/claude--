### ADD-003｜调查目标 Source 的用途、调用、数据处理及影响范围

优先级：最高优先：追加开发  
业务状态：未开始（尚未在公司工程执行）  
GitHub：https://github.com/niceon-diy/claude--/issues/4

### 目的

查明每个 Source 在哪里使用、处理什么，以及与本次追加的哪项要求有关。

### 前置任务

- [ADD-002｜从参考 Release 一览反向核对追加对应一览中的 Source 漏项](https://github.com/niceon-diy/claude--/issues/3)

按每个实际目标项目判断必要成果是否齐全，或是否有不适用依据；不是要求等待前置任务的全部项目一起完成。

### 输入

- 追加对应一览及 ADD-002 确认的漏列 Source 候选
- 实际 Source、调用方、相关 JCL／配置／共通部件、设计资料

### 实际执行步骤

1. 确认每个 Source 的实际存在、语言、版本和业务用途。若是 COBOL，先索引 SECTION 和主要处理的位置。
2. 从启动入口追踪直接／间接调用、重要实参、输入输出文件、DB Object 和外部 IF。动态调用或无法确定的值保留为未确定。
3. 将文件作成、DB 改修、检查、转换、报表等具体处理关联到代码位置和设计项。
4. 调查追加内容影响的调用方、被调用方、共通部件和数据格式，区分单纯同名与实际关系。
5. 用小白也能懂的方式说明各 Source 的用途、输入、条件分支、输出和异常处理，区分推测与事实。

### 成果物

- Source 用途与追加项目对应表
- 调用及数据输入输出关系图或边表、影响范围与未解决的动态关系

### 完成条件

- [ ] 同时覆盖原一览中的 Source 和确认漏列的 Source
- [ ] 主要关系均有代码、配置或设计位置
- [ ] 没有将未读取、无法访问、未解决解释为不存在

### 缺失或失败时

保存缺失项、实际已检查范围、受影响结论／对象、确认人或资料及最短补充方式，并继续可独立完成的工作。重要规格矛盾不能擅自消解；没有执行、没有生成或没有测试的内容不得报告完成。

## 日本語（単独でコピーして実行可能）

### ADD-003｜対象Sourceの用途・呼出し・データ処理・影響範囲を調査する

優先区分：最優先：追加開発  
業務状態：未着手（会社工程で実行前）  
GitHub：https://github.com/niceon-diy/claude--/issues/4

### 目的

各Sourceがどこで使われ、何を処理し、今回追加のどの要求に関係するかを明らかにする。

### 前提チケット

- [ADD-002｜参考Release一覧から追加対応一覧のSource漏れを逆照合する](https://github.com/niceon-diy/claude--/issues/3)

各実案件について必要な成果が揃うか、不適用の根拠があるかを判定する。前提チケットの全案件が一斉に完了するまで待つ意味ではない。

### 入力

- 追加対応一覧とADD-002で確認された漏れを含むSource候補
- 実Source、呼出し元、関連JCL／設定／共通部品、設計資料

### 実際に行う手順

1. 各Sourceの実在・言語・版・業務用途を確認する。COBOLならSECTIONと主要処理の位置を先に索引化する。
2. 起動入口から直接・間接の呼出しと重要な実引数、入出力ファイル、DB Object、外部IFを追う。動的呼出しや解決できない値は未確定として残す。
3. ファイル作成、DB改修、チェック、変換、帳票などの具体的な処理をコード位置と設計項に結び付ける。
4. 追加内容から影響を受ける呼出し先・呼出し元・共通部品・データ形式を調べ、単なる名称一致と実際の関係を分ける。
5. 各Sourceの用途、入力、条件分岐、出力、異常時処理を初心者にも分かる説明にし、推測と事実を区別する。

### 成果物

- Source用途・追加項目対応表
- 呼出しとデータ入出力の関係図または辺表、影響範囲と未解決動的関係

### 完了条件

- [ ] 原一覧のSourceと確認漏れSourceの両方が対象になっている
- [ ] 各主要関係にコード・設定・設計の位置がある
- [ ] 未読・不可アクセス・未解決を不存在として扱っていない

### 不足・失敗時

不足項、実際に調べた範囲、影響する結論／対象、確認先・資料と最短の補充方法を保存し、独立して進められる作業は続ける。重要な仕様矛盾を勝手に解消せず、未実行・未生成・未試験の内容を完了と報告しない。

この作業は、会社内で実際にアクセスできる業務工程に対して実行する。本リポジトリは依頼とテンプレートを提供するもので、会社の調査・実装・試験が完了した証拠ではない。

- まず実工程で有効なルール、現在タスク、既存成果を読む。すでに調べられる情報をユーザーへ再入力させない。歴史資料にある権限や特定環境を現在の承認とみなさない。

- 案件単位で前提を判定する。目標14案件がすべて揃うまで、準備済み案件の設計・開発を止めない。数を合わせるための架空案件を作らない。
- 正式要求、今回の対応一覧、現行設計、歴史参考を区別する。参考Source Diffを今回の正式仕様の代わりにしない。
- 重要結論に実ファイル・版・行／章／シート等の位置を付ける。事実、推測、未読、アクセス不能、未確認、不適用を区別し、不適用には理由を残す。

- 実際の完了条件を満たしてからIssueを終了する。コピー、スクリプト成功、用例生成、Source保存だけで調査や試験全体の完了としない。
