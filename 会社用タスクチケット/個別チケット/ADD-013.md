最终核对追加改修实现与设计、测试、变更对象的一致性，形成公司可交接的状态。

### 前置任务

- [ADD-010｜实现追加改修 Source，执行构建和静态检查](https://github.com/niceon-diy/claude--/issues/11)

### 输入

- 有效对应一览、基本／详细设计、实际 Source Diff、DB 环境矩阵

### 实际执行步骤

1. 从正式要求核对设计、Source 和测试，再从实际改修 Source 反向照合依据和测试。
2. 评审真实 Diff，检查对象漏项、无关变更、异常／数据／位数／返回值不一致，完成必要修复和影响复测。
3. 将变更／新增／删除 Source、相关生成物、DB Object 及目标环境与实际变更成果核对，区分 Release 对象候选和待确认项。
4. 索引设计版本、Source 版本、测试证据、恢复／重开步骤、剩余工作和成果位置，交给公司既有评审／验收流程。
5. 按项目说明完成或未完成依据，最终统计不遗漏目标 14 个项目中未确定或未调查的项目。

### 成果物

- 最终对应及变更对象一览、设计／Source／测试追踪、代码评审记录
- 各项目结束状态、交接总索引、剩余工作与恢复／继续步骤

### 完成条件

- [ ] 全部变更和全部目标要求均有双向追踪
- [ ] 没有隐瞒测试失败或未确认项而标为完成

### 修改范围

范围截至评审与交接。本番 Release 实施依照公司的单独步骤与实施范围。

### 缺失或失败时

保存缺失项、实际已检查范围、受影响结论／对象、确认人或资料及最短补充方式，并继续可独立完成的工作。重要规格矛盾不能擅自消解；没有执行、没有生成或没有测试的内容不得报告完成。

### 目的

実装した追加改修と設計・試験・変更対象が一致するか最終確認し、会社で引き継げる状態にする。

### 前提チケット

- [ADD-010｜追加改修のSourceを実装しビルド・静的確認を行う](https://github.com/niceon-diy/claude--/issues/11)
- [ADD-011｜単体テストを設計・生成・実行し失敗を修正する](https://github.com/niceon-diy/claude--/issues/12)

各実案件について必要な成果が揃うか、不適用の根拠があるかを判定する。前提チケットの全案件が一斉に完了するまで待つ意味ではない。

### 入力

- 有効な対応一覧・基本／詳細設計、実Source Diff、DB環境表
- 単体と接続テスト結果、未解決課題、会社のRelease／レビュー様式

### 実際に行う手順

1. 正式要求から設計・Source・試験を確認し、実際の変更Sourceからも逆方向に根拠と試験を照合する。
2. 実Diffをレビューし、対象漏れ、不要変更、例外・データ・桁・戻り値の不整合を調べる。必要な修正と影響再試験を完了させる。
3. 変更・追加・削除Source、関連生成物、DB Objectと対象環境を現実の変更・成果と突き合わせ、Release対象候補と未確定を分ける。
4. 設計版、Source版、試験証拠、復旧／再開手順、残件、成果場所を索引化し、会社の既存レビュー／受入手順へ渡す。
5. 案件ごとに完了／未完了の根拠を示し、14件の目標に対して未特定・未調査案件を最終集計から落とさない。

### 成果物

- 最終対応・変更対象一覧、設計／Source／試験追跡、コードレビュー記録
- 案件別終了状況、引継ぎ総索引、残件と復旧・継続手順

### 完了条件

- [ ] 全変更と全対象要求の両方向の追跡がある
- [ ] 試験失敗や未確認を隠して完了にしていない
- [ ] 本番適用済みとは宣言せず、引渡し可能範囲を正確に示している

### 変更範囲

レビューと引継ぎまで。本番Releaseの実行は会社の別手順・実施範囲による。

### 不足・失敗時

不足項、実際に調べた範囲、影響する結論／対象、確認先・資料と最短の補充方法を保存し、独立して進められる作業は続ける。重要な仕様矛盾を勝手に解消せず、未実行・未生成・未試験の内容を完了と報告しない。

### 会社Claudeへの共通実行条件

この作業は、会社内で実際にアクセスできる業務工程に対して実行する。本リポジトリは依頼とテンプレートを提供するもので、会社の調査・実装・試験が完了した証拠ではない。

- まず実工程で有効なルール、現在タスク、既存成果を読む。すでに調べられる情報をユーザーへ再入力させない。歴史資料にある権限や特定環境を現在の承認とみなさない。
- 必要な前提が揃う通常作業は連続実行する。結果を左右する重要な業務判断・権限・アクセス不足だけを具体的に確認し、それに依存しない作業は続ける。
- 案件単位で前提を判定する。目標14案件がすべて揃うまで、準備済み案件の設計・開発を止めない。数を合わせるための架空案件を作らない。
- 正式要求、今回の対応一覧、現行設計、歴史参考を区別する。参考Source Diffを今回の正式仕様の代わりにしない。
- 重要結論に実ファイル・版・行／章／シート等の位置を付ける。事実、推測、未読、アクセス不能、未確認、不適用を区別し、不適用には理由を残す。
