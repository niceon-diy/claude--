# 单程序静态调查清单／単本プログラム静的調査チェックリスト

整理日期／整理日：2026-11-03

本文件将 COBOL／DB2 单程序调查要求整理成可核对清单。使用实际资料形成结论，不表示本仓库已经解析公司 Source 或执行验证。
実資料を根拠にCOBOL・DB2の単本調査を行うためのチェックリストです。会社Sourceの解析や検証を本リポジトリで実施済みという意味ではありません。

## 中文

<a id="static-checklist"></a>

### 1. 输入与解析范围声明

输入至少包含一个实际 COBOL Source 的路径；可补充编译参数、编译器／方言、DB2／批处理环境、相关 Source／COPYBOOK、表定义和已有运行日志。记录版本或哈希、编码及实际可访问范围，不为调查擅自执行业务程序或 DB 操作。

完整读取目标文件，可分段处理但必须核对区间覆盖。读取失败或路径无效时直接记录原因，不推测文件内容。先输出范围声明，包含：

- 实际文件路径、版本、PROGRAM-ID。
- 是否存在嵌入 SQL、文件 I/O；所有可见 COPY、CALL、EXEC SQL CALL 的位置与目标。
- 可见 SQL 的表／视图名、文件逻辑名和已知物理名；不能从缺失配置补造物理路径。
- 被调用程序、COPYBOOK 内容、表结构、已有动态日志是否提供、实际读取到什么程度。
- 单文件模式的高置信度结论仅来自本文件明确证据。文件外节点与资源保持“未解析”或“基于本文件的推测”；即使资料存在，也不能当成已经读取或验证。
- 若后续明确扩大范围并实际读取外部资料，另记资料及版本、范围变化和独立证据，不把扩展结论追记成原本的单文件结论。

### 2. 调用骨架：可见调用点完整，未知部分保留

“完整骨架”指把本文件所有可见直接调用点及其目标列全，不表示已经解析全部传递调用或所有运行时可达路径。

1. 从本程序节点列出全部 CALL／EXEC SQL CALL；同一目标被多个位置调用时，保留每个调用点及条件。
2. 字面目标有明确程序名但 Source 未提供时，建立“外部节点（Source 未提供）”，保留在图和清单中，不推测其内部逻辑或再调用目标。
3. 非字面／动态目标建立“运行时决定的目标”占位，记录控制它的实际变量与可见赋值证据。不能凭变量名推断具体外部程序或遗漏该节点。
4. 标记解析状态：本文件已解析、外部未提供、非字面目标、COPYBOOK 缺失、其他待确认。
5. 用 Mermaid 或树形结构显示骨架，并关联本文件内可确认的入口、SECTION／段落及 PERFORM 路径。静态存在只证明可能调用，不证明某次运行必然发生。
6. 要把链路继续解析到外部叶节点，列明尚需取得的 Source、COPYBOOK、表结构或日志；取得并读取后才能另行扩展。

调用点表至少包含：

| 字段 | 填写要求 |
| --- | --- |
| 位置与目标 | 实际文件:行号，字面程序名或非字面目标 |
| 目标解析状态 | 本文件可确认／外部 Source 未提供／非字面／其他 |
| 触发条件 | 无条件、IF、EVALUATE／WHEN、PERFORM、循环及可见的其他条件 |
| 重要参数 | CALL USING／SQL CALL 的实际参数、方向或传递方式（源码可见时）、用途与不足依据 |
| 可见下游访问 | 仅列本文件中有依据的相关 SQL／文件访问；否则写“目标在文件外，无法确认” |
| 依据与置信度 | 实际位置、判断依据、高／中／低；低置信度标【需人工确认】 |

### 3. 相关资源、用途与副作用

完整列出本文件可见资源：本程序、所有调用目标（含动态占位）、COPYBOOK、SQL 表／视图、逻辑／物理文件、其他引用对象。资源缺失时保留记录，不因没有 Source 而删掉名称。

每个资源必须同时解释“它是什么”和“本程序怎样使用”，不能只列名称或 ID。可见的调用上下文、参数、SQL、COPY、I/O 和注释可以作为依据；仅凭命名或文件外关系推测时，说明“基于本文件证据的可能用途”，依据不足则明确待人工确认。

| 字段 | 填写要求 |
| --- | --- |
| 资源名称／ID、种类 | Source／被调用程序、COPYBOOK、表、视图、文件、其他；保留真实标识 |
| 名词说明 | 说明该对象是什么；技术名称首次出现时简释 |
| 角色与用途 | 本文件中用于什么处理；文件外用途为有依据的可能解释 |
| 访问与副作用 | 可见的读取、新增、更新、删除、文件写入、打开／关闭、提交／回滚等及触发条件；没有证据的外部副作用不写成事实 |
| 关联方式与位置 | CALL、SQL、COPY、文件 I/O 的真实文件:行号 |
| 解析状态、置信度 | 本文件已解析／外部未提供／COPYBOOK 缺失／非字面／仅名称推测；高／中／低 |
| 补充材料 | 为确认用途、接口、布局或副作用还需哪些 Source、定义、配置或日志；低置信度标【需人工确认】 |

文件外表结构、字段、约束和被调用程序的内部数据处理不得编造；本文件没有出现 SQL，也不能据此认定被调用程序不访问 DB。

### 4. 触发条件、分支与循环语义

对涉及 CALL、SQL 和文件操作的 IF、EVALUATE／WHEN、PERFORM 及循环，记录实际位置、自然语言业务解释、触发的操作、参数和资源、前置条件、可能不执行的分支以及证据／置信度。

条件语义不能只抄语法，也不能把名称推测当业务规则。沿入口至目标操作检查条件组合和循环边界，无法确认的业务含义、异常与漏项候选分别记录；未读外部节点的条件不能补造。

### 5. SQL、文件状态与数据一致性观察

在本文件可见范围内逐项检查：

- SQL 中的实际表／视图与 SELECT、INSERT、UPDATE、DELETE 等操作，及其条件、参数和可见数据关联。
- SQLCODE、FILE STATUS 和相关异常分支是否检查返回状态；有处理、无处理、无法判断分别记录位置和依据。
- 文件打开、读写、改写、删除、关闭及可见事务提交／回滚的处理顺序与异常路径。
- 原历史例子提到的 FILE STATUS 9W／9R 仅作为需核实的环境示例。按实际编译器、文件处理组件和运行环境确认状态码含义及适用性，不能把原例映射当所有 COBOL／DB2 环境的通用定义。
- 发现未处理状态或顺序异常时，写明源码位置、风险候选、成立前提和待确认内容。没有表定义、约束或外部 Source 时，不声称已确认外部一致性规则。

静态观察不能代替实际运行或测试，也不能把“存在错误分支”直接当作已经验证所有异常情况。

### 6. 证据、置信度与人工确认

所有分析结论表包含“依据（文件:真实行号）”和“置信度”；引用外部未解析对象时，依据是本文件的调用点、COPY 或 SQL 位置，不虚构外部行号。

| 置信度 | 判定与表达 |
| --- | --- |
| 高 | 本文件中存在直接、无歧义的证据，结论限定在该证据能支持的范围 |
| 中 | 本文件有间接证据，或需要基于明确的 COBOL／DB2 知识作有限推导；写出推导条件，不把推导等同已验证事实 |
| 低 | 外部 Source 未提供、COPYBOOK 缺失、REDEFINES／指针别名、动态目标、跨程序边界、仅凭名称推测用途等；写明限制并加【需人工确认】 |

未知节点、低置信度及“依据不足”项目集中列出，并说明确认所需材料。不同版本、证据冲突和读取失败单独保留；不能为了表格完整而填入猜测。

### 7. 交付与覆盖复核

输出可追溯的 MD 主报告，按实际需要生成图或图解 HTML。完整报告包含：

1. 解析范围、输入版本、读取情况和不足材料。
2. 带解析状态的调用骨架。
3. 调用点表：位置、目标、状态、条件、参数、可见下游访问、依据、置信度、人工确认。
4. 资源表：名称、种类、名词说明、角色／用途、可见访问和副作用、依据、状态、置信度、补充材料。
5. 条件分支与循环语义表。
6. SQL／文件异常与数据一致性观察表。
7. 全部未解析节点、非字面目标、低置信度及人工确认清单。
8. 结论、仍未确认的范围及扩展到外部节点所需的 Source／COPYBOOK／定义／日志。

对照实际 Source 逐个核实所有可见 CALL、COPY、SQL、文件操作的位置是否进入清单；核对重复调用点、动态占位和未读资源没有在汇总时消失。图、表、来源版本与真实行号相互对应。未知范围仍存在时，如实报告当前覆盖，不宣布整个系统已完整解析。

本清单支持 ADD-003、[LATER-003](../../追加开发/任务票/个别任务/LATER-003.md)的证据与解说；需要新建解析角色时，按[LATER-002](../../追加开发/任务票/个别任务/LATER-002.md)另行评估候选构成。[总任务](https://github.com/niceon-diy/claude--/issues/22)中的实际 Source 改修和测试继续按各任务执行，不因静态报告完成而认定业务任务完成。

## 日本語

<a id="static-checklist-ja"></a>

### 1. 入力と解析範囲の宣言

最低限、実際のCOBOL Sourceのパス一つを入力とします。コンパイル引数、コンパイラー・方言、DB2・バッチ環境、関連Source・COPYBOOK、表定義、既存実行ログを補足できます。版・ハッシュ、文字コード、実アクセス範囲を記録し、調査のために業務プログラムやDB操作を無断で実行しません。

対象全体を読み、分割する場合も区間の網羅を確認します。読取り失敗や無効パスは原因を直接記録し、内容を推測しません。最初に次の範囲宣言を出します。

- 実ファイル、版、PROGRAM-ID。
- 埋込みSQL・ファイルI/Oの有無と、可視の全COPY・CALL・EXEC SQL CALLの位置と対象。
- 可視SQLの表・ビュー、論理ファイルと判明している物理名。不足設定から物理パスを作らないこと。
- 呼出し先、COPYBOOKの内容、表構造、既存動的ログの提供・実際の読取り状況。
- 単本モードの高信頼度結論は本ファイルの明確な証拠のみを根拠とする。外部ノード・リソースは未解析または本ファイルに基づく推定とし、資料が存在するだけで読取り・検証済みとしないこと。
- 後で明示的に範囲を広げ外部資料を実際に読んだ場合は、資料・版・範囲変更・独立証拠を別記し、元の単本結論へ遡って混ぜないこと。

### 2. 呼出し骨格：可視点を列挙し未知部分を保持する

「完全な骨格」は本ファイルで可視の直接呼出し点と対象を全て記録する意味です。全ての間接呼出しや実行時到達経路を解析済みという意味ではありません。

1. 本プログラムから全CALL・EXEC SQL CALLを列挙します。同じ対象が複数箇所から呼ばれる場合も、呼出し点・条件をそれぞれ保持します。
2. リテラル対象に明確な名前があってもSource未提供なら「外部ノード（Source未提供）」を作り、図と一覧へ残します。内部処理・再呼出し先を推測で展開しません。
3. 非リテラル・動的対象は「実行時に決定する対象」として残し、制御する実変数・可視の代入根拠を記録します。変数名から具体的な外部プログラムを推定せず、ノードも省略しません。
4. 本ファイルで解析済み、外部未提供、非リテラル、COPYBOOK欠落、その他要確認の状態を付けます。
5. Mermaidまたはツリーで骨格を示し、確認可能な入口・SECTION・段落・PERFORM経路を関連づけます。静的存在は呼出し可能性を示すだけで、特定実行で必ず起きる証拠ではありません。
6. 外部の葉ノードまで解析を続けるために必要なSource・COPYBOOK・表構造・ログを列挙し、取得・読取り後に範囲を拡張します。

呼出し点表には次を含めます。

| 項目 | 記入内容 |
| --- | --- |
| 位置・対象 | 実ファイル:行、リテラル名または非リテラル対象 |
| 対象の解析状態 | 本ファイルで確認可能・外部Source未提供・非リテラル・その他 |
| 条件 | 無条件、IF、EVALUATE・WHEN、PERFORM、ループ、可視のその他条件 |
| 重要引数 | CALL USING・SQL CALLの実引数、Sourceで見える方向・渡し方、用途と不足根拠 |
| 可視の下流アクセス | 本ファイルに根拠がある関連SQL・ファイルアクセスのみ。なければ「対象は外部、確認不可」 |
| 根拠・信頼度 | 実位置、判断根拠、高・中・低。低は【人手による確認が必要】 |

### 3. 関連リソース・用途・副作用

本ファイルで可視の全リソース、すなわち本プログラム、全呼出し先と動的占位、COPYBOOK、SQL表・ビュー、論理・物理ファイル、その他の参照物を列挙します。不足するSourceがあっても記録・名前を消しません。

各リソースは「何か」と「本プログラムがどう使うか」の両方を説明し、名前・IDだけを並べません。可視の呼出し文脈・引数・SQL・COPY・I/O・コメントを根拠にし、命名や外部関係だけの推定は「本ファイルの根拠に基づく可能な用途」と示します。根拠不足なら要人手確認とします。

| 項目 | 記入内容 |
| --- | --- |
| 名称・ID・種別 | Source・呼出し先、COPYBOOK、表、ビュー、ファイル、その他。実識別子を保持 |
| 名詞説明 | 対象が何か。初出の技術用語を簡潔に説明 |
| 役割・用途 | 本ファイルのどの処理に使うか。外部用途は根拠のある可能な説明 |
| アクセス・副作用 | 可視の読取り・追加・更新・削除・ファイル書込み・開閉・コミット・ロールバックなどと条件。証拠のない外部副作用を事実にしない |
| 関連方式・位置 | CALL・SQL・COPY・ファイルI/Oの実ファイル:行 |
| 状態・信頼度 | 本ファイル解析済み、外部未提供、COPYBOOK欠落、非リテラル、命名のみの推定。高・中・低 |
| 補足資料 | 用途・インターフェース・レイアウト・副作用を確認するSource・定義・設定・ログ。低信頼度に【人手による確認が必要】 |

外部の表構造・項目・制約・呼出し先内部のデータ処理を捏造しません。本ファイルにSQLがないことだけで、呼出し先がDBへアクセスしないとは判断できません。

### 4. 条件・分岐・ループの意味

CALL・SQL・ファイル操作に関連するIF、EVALUATE・WHEN、PERFORM、ループについて、実位置、自然言語による業務説明、発火する操作、引数・リソース、前提条件、実行されない可能性のある分岐、根拠・信頼度を記録します。

構文の写しだけで済ませず、命名からの推測を業務ルールとしません。入口から操作までの条件の組合せ・ループ境界を確認し、不明な業務意味、異常、欠落候補を分けて記録します。未読外部ノードの条件を作りません。

### 5. SQL・ファイル状態・データ整合性の観察

本ファイルで可視の範囲について確認します。

- 実際の表・ビュー、SELECT・INSERT・UPDATE・DELETEなどのSQL、条件・引数・可視のデータ関係。
- SQLCODE・FILE STATUS・異常分岐が戻り状態を確認しているか。処理あり・なし・判断不可を位置と根拠付きで区別。
- ファイルの開く・読む・書く・書き換える・削除・閉じる処理と、可視のコミット・ロールバックの順序・異常経路。
- 履歴例のFILE STATUS 9W・9Rは、環境を確認するための例に限定。実コンパイラー、ファイル処理機構、実行環境でコードの意味・適用性を確認し、全COBOL・DB2共通の定義としない。
- 未処理状態や順序の問題候補は、実位置、リスク候補、成立前提、要確認を記録。表定義・制約・外部Sourceが不足する場合、外部整合性ルールを確認済みとしない。

静的観察は実行や試験の代わりではありません。「異常分岐がある」だけで全異常ケースの検証済みとは扱いません。

### 6. 根拠・信頼度・人手確認

全分析結論表に「根拠（実ファイル:実際の行番号）」と「信頼度」を含めます。未解析外部対象の根拠は本ファイルの呼出し・COPY・SQL位置で、外部行を捏造しません。

| 信頼度 | 判定・表現 |
| --- | --- |
| 高 | 本ファイルに直接かつ無曖昧の根拠があり、その根拠で支えられる範囲に結論を限定 |
| 中 | 本ファイルの間接証拠、または明確なCOBOL・DB2知識からの限定的推論。条件を明記し、推論を検証済み事実と同一視しない |
| 低 | 外部Source未提供、COPYBOOK欠落、REDEFINES・ポインター別名、動的対象、プログラム境界、命名だけの用途推定など。制約を示し【人手による確認が必要】を付ける |

未知ノード、低信頼度、根拠不足をまとめ、確認に必要な資料を示します。版違い、証拠の衝突、読取り失敗は独立して残し、表を埋めるための推測をしません。

### 7. 納品・網羅の再確認

追跡可能なMD主報告を出し、実際の必要に応じて図や図解HTMLを生成します。完全な報告には次を含めます。

1. 解析範囲、入力版、読取り状況、不足資料。
2. 解析状態付きの呼出し骨格。
3. 呼出し点表：位置、対象、状態、条件、引数、可視の下流アクセス、根拠、信頼度、人手確認。
